## Review findings and their state

A fresh review of the branch found 2 critical and 5 important defects. All were reproduced,
fixed and covered by tests:

| Finding | Status |
|---|---|
| Queue handover cut up to 1 s off the preceding track | fixed — waits for the device to drain; smoke asserts the measured duration |
| `feed()` could spin forever | fixed — producer dropped on `stop()`, 5 s timeout with `code="stalled"` |
| Handover never resumed `playing` | fixed — state flips under the same lock as the queue pop |
| Windows missing encoder delay | fixed — `emitted` tracks the absolute position; delay applied at the head |
| Seek re-included trailing padding | fixed — trim budget is absolute |
| Fed stream reported a fake underrun | fixed |
| Stall error coded `format` | fixed — `code="stalled"` |
| `Recorder` had no context manager | fixed |
| mono fold kept channel 0 for >2 channels | fixed — averages all channels |
| `record(inf)` panicked | fixed — rejects non-finite |

Deferred (recorded, not fixed): recorder keeps its buffer allocated after an overflow until
the next `start()`; `record()` overshoots by at most one device buffer; AAC decoded through
`load_bytes` cannot read MP4 priming without a path (documented); MP3 keeps the 47-sample
offset against libmpeg123/ffmpeg.

## Work completed after the first report

- **abi3 adopted.** `pyo3 = { features = ["abi3-py310"] }` compiles with the numpy crate and
  works at runtime (verified: a `cp310-abi3` wheel installed on Python 3.14 decodes, plays and
  passes the smoke suite). The release matrix is now one wheel per platform instead of fifteen.
- **All five platforms build and import**: Linux x86_64, Linux aarch64 (native ARM runner, the
  cross build could not find aarch64 ALSA headers), Windows amd64, macOS arm64, macOS Intel.
  The dispatch run is green; `publish` was skipped as intended.
- **CI is green end to end** on the branch: lint, tests on Ubuntu/Windows/macOS, python job
  (wheel build, smoke, golden decode, API drift), docs rebuild diff.
- **Recorder** releases its ~230 MB buffer when a take overflows.
- **README and docs** carry the 0.3.0 numbers and the abi3 platform matrix.

Documentation drift and the Windows gap are closed: the Windows job compiles and runs the full
unit/integration suite, and every public name is checked against the API page.

## Remaining, accepted

1. **Audio hardware is only tested on macOS** — Windows and Linux runners are headless, so
   playback/recording there is covered by compilation and unit tests, not by a device.
2. **`record()` overshoots by at most one device buffer** (measured 0.25 s → 0.256 s).
3. **AAC decoded through `load_bytes` cannot read the MP4 priming** (no path to the edit list).
4. **MP3 keeps a 47-sample offset** against libmpeg123/ffmpeg; length is exact.
